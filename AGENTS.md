# Working on an issue

- Read [CONTRIBUTING.md](CONTRIBUTING.md), the [documentation](docs/README.md), and the assigned issue. Verify its dependencies and start from the current default branch.
- Implement the assigned issue and its acceptance checks. Leave dependent work for its own issue.
- Keep the record format and release artifacts usable by any consumer. App-specific adapters belong in the consuming app.
- Put only original code, structured records cleared for publication, source references, and synthetic fixtures in Git. Keep raw source material out of public issue and pull request text.
- Use project-focused language in documentation, issues and pull requests. Prefer concrete project or record names to first-person phrasing.
- Use documentation for product usage and data contracts. Track progress, gaps and planned work in GitHub Issues.
- Run the checks named in the issue. Report exactly what was verified and any remaining gaps.
